When Player Class Changes

This server node is only available in Beyond Mode.

Triggers when changing to a player's class.

Output Values

  • Event Source Entity (Entity) - Player entity that changed its class.
  • Event Source GUID (GUID) - GUID of the player entity.
  • Pre-Modification Class Config ID (Config ID) - ID of the class it changed from.
  • Post-Modification Config ID (Config ID) - ID of the class it changed to.

Usage

Use this node to listen to player's class change. This can occur from Change Player Class. This node must be mounted on the player or on the class as player node graph.

This node is very similar in function as When Player Class Is Removed. The difference is that if it is mounted on the class as player node graph, this node only triggers when the player is changing to this class from another. See notes for detail.

Notes

  • Event Source Entity and Event Source GUID may not be the same as the self entity, if it was forwarded by Forwarding Event.
  • If Change Player Class is called where the changed class is the same as the previous class, then this node does not trigger. i.e. Pre-Modification Class Config ID is always different from Post-Modification Config ID.
  • This node runs after the player's class has already switched. Querying player's class with Query Player Class right after this node returns the post-modification class. Querying other values like class level or HP is also for post-modification class.
  • The order in which the class removed and changed events are triggered appears to be fixed. They always occur in the following order:
    1. When Player Class Is Removed runs on player node graph
    2. When Player Class Is Removed runs on class node graph for the previous class
    3. When Player Class Changes runs on player node graph
    4. When Player Class Changes runs on class node graph for the new class

Performance

This node took ~3 units to run on average.

Performance may vary for various reasons. These numbers are just for giving a sense of rough magnitude. Performance may differ from profiling in a test play when playing a published stage. First execution of a node within a node graph execution tends to take a bit longer.
