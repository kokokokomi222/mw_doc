Add Uniform Basic Rotation-Based Motion Device

Start a basic motion device with uniform rotational motion.

Input Parameters

  • Target Entity (Entity) - Entity with basic motion device component
  • Motion Device Name (String) - Name of the motion device to assign
  • Motion Device Duration (Floating Point Numbers) - The duration for which this motion device remains active. Unit is in seconds.
  • Angular Velocity (°/s) (Floating Point Numbers) - Angular velocity of the motion. Unit is degrees per second.
  • Rotation Axis Orientation (3D Vector) - Orientation of the rotation axis. Rotation follows the left-hand rule (see usage for detail).

Usage

Basic motion device with uniform rotational motion is typically configured in the component, where the duration, angular velocity, and the rotation axis can be specified. However, this node can create a basic motion device with uniform rotational motion dynamically, specifying the duration, angular velocity, and the rotation axis on runtime. After this node executes, the newly created basic motion device starts running immediately, without having to run Activate Basic Motion Device.

The orientation of Angular Velocity (°/s) is given using the left-hand rule relative to Rotation Axis Orientation: If left thumb points toward Rotation Axis Orientation, the left fingers curls in the direction of rotation. If Rotation Axis Orientation was pointing straight up (e.g. (0, 1, 0)) and Angular Velocity (°/s) is positive, the entity will rotate clockwise when viewed from the top.

Example

In this example, when tab is selected, the entity will start rotating with velocity of 45 degrees/second for 2 seconds where the rotation axis points toward (0, 1, 0). The entity will end up 90 degrees rotated clockwise (if viewed from top) when it stops. Note that Activate Basic Motion Device was not needed to start moving.

Notes

  • If Target Entity does not have the basic motion device component, this node raises "Entity component does not exist" error.
  • Get Entity Location and Rotation reports the correct intermediate rotation during this motion, unlike follow motion device or projectile motion device.
  • If there is already a running basic motion device on this entity named Motion Device Name, this node stops that device in the middle of the motion. However, this does not overwrite the basic motion device statically defined in the component. Below example illustrates this issue. We have a statically defined basic motion device with uniform rotational motion that turns 45 degrees clockwise per second for 3 second. In the node graph, we start that statically defined basic motion device. But one second later, we start a dynamically defined basic motion device that turns 45 degrees counterclockwise per second for 3 second. Lastly one more second later, we start the statically defined basic motion device again. All these devices have the same name: my_motion. Say the entity's rotation starts at (0, 0, 0). In this scenario, the entity turns 45 degrees clockwise in the first second, ending up at (0, 45, 0). Then this node stops that movement and turns 45 degrees counterclockwise in the next second, ending back at (0, 0, 0). And finally, the original statically defined basic motion device gets started again, turning clockwise for 3 seconds. Thus, the entity comes to rest at (0, 135, 0).

    This behavior is complicated to understand, so we recommend not using duplicate names and explicitly use Stop and Delete Basic Motion Device instead.

Performance

This node took ~30 units to run on average.

Performance may vary for various reasons. These numbers are just for giving a sense of rough magnitude. Performance may differ from profiling in a test play when playing a published stage. First execution of a node within a node graph execution tend to take a bit longer.
