Monitor Signal

Triggers when a signal is sent.

Output Values

  • Event Source Entity (Entity) - Entity that has this node graph mounted.
  • Event Source GUID (GUID) - GUID of above Entity. 0 if the entity was created dynamically.
  • Signal Source Entity (Entity) - Entity that sent the signal.

Selecting Signal Name shows the parameters of the signal as output values of the node.

Usage

Signals are custom events you can trigger. It is globally broadcasted to all entities, so any entity can listen to it using this node when a signal is sent with Send Signal. Signals can be defined in the node graph editor by opening Server Signal Explorer (from the bottom menu bar, or top menu > Window > Server Signal Explorer). The name of the signal and its parameters can be set here.

Custom variable change could be used in place of signals using When Custom Variable Changes A signal is probably better to use if multiple node graphs may want to listen to it, or if it passes multiple parameters. But if you just want to pass in one parameter to one node graph, this method may be easier to reason with, because it is limited to just the node graphs held by the entity. Also, there is a limit of 99 signals per stage.

Notes

  • Event Source Entity and Event Source GUID may not be the same as the self entity, if it was forwarded by Forwarding Event.
  • Signal Name does not have an input pin, so it must be set statically.
  • Signal Name can be selected by clicking on the magnifier icon on the right.
  • If Signal Name is not selected, the verification of the stage fails and the stage cannot be played.

Performance

This node took ~3 units to run on average.

Performance may vary for various reasons. These numbers are just for giving a sense of rough magnitude. Performance may differ from profiling in a test play when playing a published stage. First execution of a node within a node graph execution tend to take a bit longer.
