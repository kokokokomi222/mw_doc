Edit Model Color & Material

Set custom color and material of the entity.

Input Parameters

  • Target Entity (Entity) - Entity to set the custom color and material. Must be an object entity.
  • Overwrite Color Configurations (Boolean) - Yes to apply new custom color configuration values, No otherwise
  • Enable Custom Color? (Boolean) - Yes to enable the custom color, No otherwise
  • Fill Color (Integer) - The custom color to apply. 0xRRGGBB where RR is the red, GG is the green, and BB is the blue component of the color in hexadecimal. e.g. 16776960 for yellow.
  • Color Opacity (Floating Point Number) - The opacity of the custom color. Between 0 and 100, inclusive.
  • Color Blend Mode (Blend Mode Enum) - One of Override or Multiply
  • Overwrite Material Configurations (Boolean) - Yes to apply new custom material configuration values, No otherwise
  • Enable Custom Material? (Boolean) - Yes to enable the custom material, No otherwise
  • Fill Material Type (Material Enum) - One of Freeze or Petrification

Usage

Luna VIII introduced custom color and material for entities. With this feature, models can be put into different colors. This node lets you set these custom color and material values in the node graph.

Example

In this example, we set the custom color of the entity. Because Overwrite Color Configurations is Yes, the color configurations ( Enable Custom Color?, Fill Color, Color Opacity, and Color Blend Mode) are applied to the entity. However, Overwrite Material Configurations is No, so the material configurations ( Enable Custom Material? and Fill Material Type) are ignored. As a result, custom color gets enabled with 100% opacity blue with multiply blend mode.

Notes

  • Target Entity must be an object entity. If Target Entity is a stage, character, player, or creation entity, this node raises "Entity does not exist" error (can be misleading, because the non-object entity may exist).
  • Fill Color can be copied from the entity detail panel.
  • If Fill Color is at least 2^24, the lower 24 bits are used for the color. For example, if Fill Color is 16777216 = 2^24, the lower 24 bits are all 0, so the color is set to black.
  • If Fill Color is negative, the lower 24 bits of the binary representation is used for the color. Miliastra uses two's complement to represent negative integers in binary. For example, if Fill Color is -256, the binary representation of this number is 11111111111111111111111100000000, so the color is set to yellow.
  • If Color Opacity is not between 0 and 100, this input is ignored and the original opacity value is kept.
  • When Color Blend Mode is Override, it appears to use the following blending written in pseudo-shader code: output.rgb = original.rgb * (1.0-opacity/100.0) + custom_color.rgb * opacity/100.0. If the opacity is full at 100.0, the model appears to be painted uniformly by the custom color. Below is an example of a model painted blue at full opacity with Override blend mode.
  • When Color Blend Mode is Multiply, it appears to use the following blending written in pseudo-shader code: output.rgb = original.rgb * (1.0-opacity/100.0) + original.rgb * custom_color.rgb * opacity/100.0). If the opacity is full at 100.0, the model appears to be in custom color with the original. Below is an example of a model painted blue at full opacity with Multiply blend mode.
  • Material seems to be applied after the custom color is applied.
  • Models with Freeze and Petrification custom material appears like the below example.
  • Custom color and material on decorations cannot be accessed or modified by node graphs.

Performance

This node took ~5 units to run on average.

Performance may vary for various reasons. These numbers are just for giving a sense of rough magnitude. Performance may differ from profiling in a test play when playing a published stage. First execution of a node within a node graph execution tend to take a bit longer.
