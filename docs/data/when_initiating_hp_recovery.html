When Initiating HP Recovery

Triggers when an entity initiates healing.

Output Values

  • Event Source Entity (Entity) - Entity that is doing the healing.
  • Event Source GUID (GUID) - GUID of the above entity. 0 if it was dynamically created.
  • Recover Target Entity (Entity) - Entity that was healed.
  • Recovery Amount (Floating Point Numbers) - Effective healing amount. See notes for detail.
  • Recover Tag List (String List) - List of tags associated with this healing.

Usage

Use this node to listen to the event when the entity heals a target. This node must be mounted on the source of the healing. This healing can come from

  • Recover HP
  • Recover HP Directly
  • Client node "Recover Character's HP".
  • Character skills/bursts/passives/constellations, weapon passives, or artifact set effects in classic mode.

Notes

  • Event Source Entity and Event Source GUID may not be the same as the self entity, if it was forwarded by Forwarding Event.
  • If there was healing bonus or incoming healing bonus involved, Recovery Amount reflects the value after the bonus.
  • If a heal overflows (i.e. heals more than needed to reach max HP), Recovery Amount only accounts for the HP that was increased. For instance, if the entity already had full HP, then Recovery Amount is 0.
  • If current HP of Recover Target Entity is queried with Get Object Attribute in this event, it shows the HP after the healing.
  • Node graph cannot be mounted to a character in classic mode. If you want to listen to this event on a character, there is a following hack:
    1. Create an item node graph
    2. Create a dummy item that mounts the item node graph.
    3. Add an inventory component to the character and put the dummy item in the inventory.
    Then the item node graph should be able to listen to this node event for the character.

Performance

This node took ~6 units to run on average.

Performance may vary for various reasons. These numbers are just for giving a sense of rough magnitude. Performance may differ from profiling in a test play when playing a published stage. First execution of a node within a node graph execution tends to take a bit longer.
