Change Player Class

This server node is only available in Beyond Mode.

Changes player's class.

Input Parameters

  • Target Player (Entity) - Player entity to change the class for.
  • Class Config ID (Config ID) - ID of the class. e.g. 1090519041
  • Existing Skill Handling (Enumeration) - One of Clear All or Preserve Unrelated Skills.

Usage

In Miliastra's beyond mode, each player has a current class. Each class represents different capability of the current player, and the class comes with many configurations such as:

  • Camera
  • UI layout
  • Whether the player can Jump/sprint/climb/glide
  • Level
  • HP/ATK/DEF scale curve
  • Maximum stamina
  • Aggro multiplier
  • Interruption intake setting
  • Skills
  • Custom variables
  • Unit statuses
  • Node graphs

This node switches the player's class to another class.

Example

In this example, we have two classes configured: Sword user and Bow user. When a player selects the first tab, the player class is changed to Sword user. When a player selects the second tab, the player class is changed to Bow user.

Notes

  • If Target Player does not exist, this node raises "Entity does not exist" error.
  • If Target Player is not a player entity, this node is no-op.
  • If Class Config ID is not an ID of a class, this node is no-op.
  • I could not get Existing Skill Handling to show any behavior. Regardless of the argument value, the resulting skills on the player seems to be only the skills configured on the new class, not preserving any of the skills from the previous class. More testing is needed.
  • If the changed class is the same as the previous class, When Player Class Changes and When Player Class Is Removed do not trigger.

Performance

When the player successfully changed to a different class, this node took ~80 units to run on average. When the node failed or did not change to a different class, this node took ~2 units to run on average.

Performance may vary for various reasons. These numbers are just for giving a sense of rough magnitude. Performance may differ from profiling in a test play when playing a published stage. First execution of a node within a node graph execution tends to take a bit longer.
