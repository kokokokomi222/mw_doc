When Player's Activated Control Motion Device List Changes

This server node is only available in Beyond Mode.

Triggers when player changes their control motion device.

Output Values

  • Event Source Entity (Entity) - Entity of the player that changed control motion device.
  • Event Source GUID (GUID) - GUID of the player entity. e.g. 1086324738
  • Old Control Motion Device Entity List (Entity List) - List of entities that were controlled by the player before the change
  • Current Activated Control Motion Device Entity List (Entity List) - List of entities that are controlled by the player after the change

Usage

Luna VIII introduced control motion devices. An entity can have a control motion device component, then this entity's movement can be controlled directly by players instead of controlling Manekin/Manekina character. This feature can be used to create a vehicle that can be driven by players.

Use this node to listen to the event when a player changes their control motion device via Set Player to Activate Control Motion Device. This node should be in a node graph mounted on the player entity.

In this example, we have a node graph mounted on the player. When the control motion devices change for the player, we iterate through all the new active devices. For each device entity, if it is not in the old device entity list, we forward this event to the entity.

Notes

  • Event Source Entity and Event Source GUID may not be the same as the self entity, if it was forwarded by Forwarding Event.
  • If Set Player to Activate Control Motion Device was called with identical list of entities as the list of currently activated control motion device entities for the player, this event is not triggered.
  • The length of Old Control Motion Device Entity List and Current Activated Control Motion Device Entity List cannot exceed 3.

Performance

This node took ~4 units to run on average.

Performance may vary for various reasons. These numbers are just for giving a sense of rough magnitude. Performance may differ from profiling in a test play when playing a published stage. First execution of a node within a node graph execution tends to take a bit longer.
