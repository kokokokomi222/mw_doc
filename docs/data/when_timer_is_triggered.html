When Timer Is Triggered

Triggers when the timer reaches specified time.

Output Values

  • Event Source Entity (Entity) - Entity that has the timer.
  • Event Source GUID (GUID) - GUID of above Entity. 0 if the entity was created dynamically.
  • Timer Name (String) - Name of the timer.
  • Timer Sequence ID (Integer) - Index of the time that was specified by the timer. 0-indexed.
  • Number of Loops (Integer) - The number of times that a loop has been completed. Note that this value is already incremented on the last timer sequence if it is looping. See the example below for details.

Usage

First, it's important to distinguish the difference between timers and global timers. They may seem similar, but they are completely separate systems with different purposes. Global timers only fire once, but it can count up or down. Global timer is primarily used to be displayed in UI by being mounted on the stage or a player. Global timer can also be used to precisely measure a span of time. State of a Global timer can be queried by Get Current Global Timer Time.

On the other hand, timer can fire multiple times at specified moments, and it can also repeat on loop. State of a timer cannot be queried from a node graph.

Timer can be used to control when certain events occur in your game. Timer can also be used to space out computation when there's a lot of it. Use Start Timer to start a timer and then this node to listen to when the timer is triggered.

The way the value Number of Loops works is not intuitive at all. See the example for detail.

Example

In this example, we start a timer named test_timer when a character selects the tab. The list [1, 3, 7] is passed as Timer Sequence, which means it will fire the timer event at 1 second, 3 seconds, and 7 seconds after the timer starts. We also have a When Timer Is Triggered which listens to the event, and print the output of Timer Sequence ID and Number of Loops. Because Loop is set to Yes, this sequence of events will repeat as follows:
Time after timer started Timer Sequence ID output Number of Loops output
1 second 0 0
3 seconds 1 0
7 seconds 2 1
8 seconds 0 1
10 seconds 1 1
14 seconds 2 2
15 seconds 0 2
17 seconds 1 2
21 seconds 2 3
and so on.

If Loop was set to No, the behavior differs. Number of Loops is now always 0 even on the last timer sequence:
Time after timer started Timer Sequence ID output Number of Loops output
1 second 0 0
3 seconds 1 0
7 seconds 2 0

Notes

  • Event Source Entity and Event Source GUID may not be the same as the self entity, if it was forwarded by Forwarding Event.
  • The output Number of Loops increments on the event when the last timer sequence is triggered and if it is looping. See the above example for detail.
  • For maintenance of the node graph, it is recommended that Timer Name is always put into Multiple Branches or Equal so it does not unexpectedly trigger on other timers.

Performance

This node took ~6 units to run on average.

Performance may vary for various reasons. These numbers are just for giving a sense of rough magnitude. Performance may differ from profiling in a test play when playing a published stage. First execution of a node within a node graph execution tend to take a bit longer.
